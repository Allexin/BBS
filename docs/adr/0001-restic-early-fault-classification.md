# ADR 0001: ранняя классификация ошибок restic stderr

Статус: proposed

## Контекст

PoC закреплённой версии restic 0.19.1 подтвердил, что source read error поступает как
JSON event в stderr. Настоящий out-of-space на изолированном NTFS VHDX вместо JSON
event выдаёт повторяемую текстовую диагностику stderr и продолжает retry с растущими
паузами. Ожидание штатного exit code нарушает требуемый fail-fast.

## Предлагаемое решение

Snapshot adapter асинхронно читает stdout и stderr. Основным контрактом остаются JSON
events. Для restic 0.19.1 дополнительно разрешается точное сопоставление заранее
проверенных stderr diagnostics для repository write/I/O и out-of-space.

Классификатор:

- действует только для точной поддерживаемой major/minor версии restic;
- не использует локализованный вывод PowerShell или Windows shell;
- при первом совпадении немедленно инициирует cooperative termination;
- сохраняет исходную строку только в локальной диагностике с удалением путей;
- не считает неизвестный текст известной ошибкой;
- закрепляется integration-тестами на реальных fault fixtures.

Обновление restic блокируется, пока compatibility tests не подтвердят классификатор
для новой версии.

## Последствия

Fail-fast становится возможен для фактически наблюдаемого поведения restic, но часть
контракта зависит от версионно закреплённого текста stderr. Без принятия этого ADR
snapshot adapter остаётся заблокированным согласно дизайн-документу.
